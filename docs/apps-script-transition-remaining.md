# 탈 Apps Script 남은 과정

## 현재 완료 범위

- 활성 강사 31명의 과거·현재 월 시수 요약은 Supabase를 직접 읽습니다.
- 로그인 초기 데이터는 활성 강사 31명이 본인 UID 스냅샷을 Supabase에서 직접 읽습니다.
- Firebase Auth 로그인 후 계정 역할·강사명·프로필·업무 링크는 Firestore canonical 문서를 직접 읽습니다.
- 수강생 통합 관리의 전체 학생 월별 요약은 승인된 관리자 권한으로 직접 읽습니다.
- 전체 승인 관리자의 학생 월별 통계와 공지·과목 선택·마스터 상태는 Supabase를 직접 읽습니다.
- 수업일지와 시수 동의는 Supabase RPC에 직접 저장하며 Apps Script로 우회하지 않습니다.
- Access CSV/붙여넣기 분석과 업로드는 브라우저 검증 엔진과 관리자 전용 Supabase RPC를 사용하며 Apps Script를 경유하지 않습니다.
- Notion 수업일지 기능은 데이터와 설정을 삭제하지 않은 채 UI, 조회 집계, 동기화 엔드포인트를 보류 처리했습니다.
- 직접 저장은 강사 범위, 멱등성, 트랜잭션, 감사 로그와 영향 월 캐시 무효화를 적용합니다.
- 직접 조회가 누락·지연·오래된 상태이면 기존 Apps Script로 자동 복귀합니다.
- 마스터 동기화와 아직 이전하지 않은 복합 기능은 기존 서버 경로를 유지합니다.

## 남은 작업

1. **관리자 학생 통계 직접 조회 확대 — 완료**
   - 특정 UID 대신 관리자 capability와 Supabase RLS를 함께 사용합니다.

2. **단순 읽기 API 이전 — 1차 완료**
   - 공지, 과목 선택 정보, 마스터 동기화 상태를 직접 조회합니다.
   - 일정과 일부 복합 관리자 조회는 canonical 테이블·응답 스키마 정리가 더 필요합니다.

3. **운영 쓰기 서버 이전 — 시수 동의·Access 업로드 완료**
   - 수업일지·시수 동의는 제한 RPC로 이전했습니다.
   - 일반 출결 입력과 과목 선택 저장 등 나머지 쓰기는 별도 전환이 필요합니다.

4. **배치·외부 연동 이전**
   - 마스터 동기화와 예약 작업을 Edge Function/스케줄러로 옮깁니다.
   - Notion 연동은 보류 상태이므로 재개 결정 전에는 이전 범위에서 제외합니다.
   - 서버 비밀키는 브라우저나 GitHub Pages에 노출하지 않습니다.
   - 현재 Supabase Functions/Vault에는 Google Sheets·Notion 자격 증명이 없습니다. 자격 증명 이전 전에는 기존 연동을 제거하지 않습니다.

5. **Apps Script 호환 브리지 제거**
   - 모든 읽기·쓰기·배치의 운영 검증이 끝난 뒤에만 `google.script.run`과 Apps Script 배포를 제거합니다.
   - 그 전까지는 장애 시 즉시 복귀할 수 있는 fallback으로 유지합니다.
   - `saveClassLogRows`, Access 분석·업로드는 브리지에서 제거됐지만, 전체 브리지는 32개 action이 남아 있어 아직 제거 조건을 충족하지 않습니다.
