# 운영 수업일지 1인 파일럿 — 2026-09-28

## 최신 상태: 전체 강사 확대 승인 반영

사용자의 “네, 확대하세요” 승인으로 서버 단일 계정 제한(pilotUids)을 제거하고 rolloutStage=general로 변경했다. 기존 인증·활성 계정·강사 역할·앱 접근·초안 소유자 검사는 그대로 유지한다. 공개 기능 플래그를 true로 전환하고 설정 스크립트 캐시 버전을 2로 올렸다. 기본 수업일지 메뉴는 새 작성 화면이며 기존 Fillout 버튼은 유지한다.

기존 초안 제출 대상 비교를 깨뜨리지 않도록 environment 값은 production-pilot을 보존했다. 실제 전송은 동일 운영 DB이고 단계 표시는 rolloutStage를 따른다. 테스트 fixture는 없으며 verificationUids는 빈 배열이다. 권한 및 회귀 테스트 31개 통과. 관리자 전용 계정 중 강사 Notion 연결이 없는 계정은 작성 원본 보존 후 연결 확인이 필요하며, 실무자 초안 접근 권한은 확대하지 않았다.

아래는 확대 전 검증 이력이다.

사용자 승인에 따라 운영 준비와 안준성 계정만의 제출을 활성화했다.

- 운영 Notion 데이터 소스에 `Portal draft ID` rich_text 속성 추가. 기존 일지 본문과 수강 배정은 변경하지 않았다.
- 기존 Fillout 강사 페이지 ID 및 확정된 학생 공개 Notion 연결을 대조하여 강사 30명, 학생 119명 매핑 저장. 중복 대상 0건. 대조되지 않은 강사 2명과 학생 3명은 자동 연결하지 않았다.
- 운영 스키마 preflight 및 안준성·박성민 매핑 검증 통과.
- runtime은 `enabled: true`, `pilotUids`는 안준성 한 명, `environment: production-pilot`. 테스트 fixture는 제거했다.
- 공개 기본 진입은 Fillout 유지. 새 작성 화면은 `https://sedubanpo.github.io/t-portal/?lesson_log_pilot=1`로 진입하며 서버에서 계정을 제한한다.
- 학생 선택은 담당 여부와 관계없이 활성 학생의 최소 정보만 제공한다. 타인 초안 수정·대리 제출은 허용하지 않는다. 연결 미확정 학생의 최종 제출은 차단하며 초안은 보존한다.
- 새 초안 생성 시 전송 대상을 고정한다. 환경이 바뀐 초안의 제출을 차단하고, worker는 현재 설정 대신 제출 당시 고정 대상을 사용한다. 대상 정보 없는 이전 대기 건은 검토 상태로 보존한다.

## 검증

- 단위/클라이언트/권한/홈 회귀 테스트: 31개 통과.
- 격리된 Firebase 에뮬레이터 및 Notion 테스트 DB 통합 시나리오: 12개 통과.
- HTTP·예약·이벤트 함수 3개 배포 성공.
- 운영 전환 후 149개 매핑, 파일럿 1명, 운영 대상, 테스트 fixture 제거를 재확인했다.
- 실제 운영 일지 제출은 대신 실행하지 않았다. 첫 실제 제출 결과는 아직 미검증이다.
- 실제 iPhone 오프라인 및 파일 첨부 검증은 미완료이며, 사용자 요청에 따라 네트워크를 끄지 않았다.

2026-09-28 Chrome에서 사용자가 안준성으로 직접 로그인한 세션으로 검증했다.

- 파일럿 수업일지 진입 및 활성 학생 선택 목록 표시 확인.
- `[PC 검증·미제출] 자동저장 복구`라는 명시적 시험 초안을 생성하고 본문을 입력해 `저장됨` 확인.
- 브라우저 새로고침 후 목록에서 다시 열어 본문이 정확히 복원됨을 확인.

## 전체 확대 전 후속 확인 (초기 조사 기록)

- 미연결 강사로 집계된 2명은 김용찬·에스에듀 관리자 계정이며 기존 Fillout 강사 ID가 없다. 일반 강사 연결 누락과 구분한다. 자동으로 강사 페이지를 만들지 않았다.
- 김서윤b의 기존 확정 publicPageId는 같은 학생 DB의 활성 `김서윤b[구분주의]` 페이지를 가리킨다. 제목 완전일치 검사 때문에 제외됐다. 별도 김서윤 페이지가 있으므로 접미어를 전역 제거하는 우회는 하지 않는다.
- 김주안·송태영은 같은 이름의 활성 Notion 후보가 있으나 확정 binding이 없다. 이름만으로 연결하지 않고 사용자 확인을 요청했다.
- 사용자가 안준성·박성민 시험 일지 1건 및 가상 PNG·PDF 제출을 승인했다. 제목 `[연동 검증·실제 수업 아님]` 초안을 PC에서 작성·저장했다. 이 시점에는 아직 제출하지 않았다.
- PNG·PDF는 개인정보 없는 시험 문서를 생성·렌더링하여 준비했다. 확장 파일 업로드는 file URL 접근 권한 부족으로 실패했고, 기본 선택창 키 입력도 전달되지 않아 사용자에게 두 파일 선택을 요청했다. 확장 권한은 변경하지 않았다.
- 재검증: 회귀 31개 통과, 운영 API 미인증 401 및 비허용 Origin 차단 확인.
- 읽기 전용 `scripts/verify-approved-production-journal.cjs`는 제출 후 단일 페이지, 필드·본문·강사/학생 관계, PNG/PDF 원본 SHA-256 일치를 검증한다. 제출 전에는 성공으로 보고하지 않는다.

## 후속 검증 완료 및 학생 연결 반영

- 사용자 PC 제출 완료 후 운영 Notion을 읽기 검증했다. 시험 draft `05c7eea2-cd0e-4e6f-9855-422567ac03c3`, Notion 페이지 `3e8d8b62-80e7-818b-ac87-de236a74269d` 한 건만 존재한다. 필드·본문·강사/학생 관계가 저장된 원본과 일치한다.
- PNG 29,483 bytes 및 PDF 1,727 bytes를 Notion에서 읽어 원본 파일의 SHA-256과 일치함을 확인했다. 추가 시험 제출은 하지 않았다.
- 사용자가 김주안·김서윤b 연결을 확인했다. 지정된 페이지 UUID·데이터 소스·활성 여부·수정된 제목을 재검증하고 두 학생의 수업일지 전용 매핑을 원자적으로 반영했다. 기존 학생 master, 수강 배정, 공용 binding, Notion 내용은 변경하지 않았다.
- 송태영은 사용자가 중지생으로 확인했으므로 신규 연결 보완 대상에서 제외했다. 학생 master 상태는 임의로 수정하지 않았으며, 기존 작성 목록에 나타나는 상태 불일치의 별도 확인 여지는 남는다.
- 매핑 반영 후 두 학생 모두 verified=true, 운영 대상 일치 및 1인 파일럿 유지 확인. 전체 계정 활성화와 기본 Fillout 전환은 아직 하지 않았다.

## 운영 및 되돌리기

안준성 계정은 새 주소에서 새 일지를 작성한다. 테스트에서 만든 초안을 운영 제출용으로 재사용하지 않는다. 다른 계정은 기존 Fillout을 사용한다.

문제 발생 시 runtime의 `enabled`를 false로 하고 `verificationUids`를 빈 배열로 유지하여 새 기능을 중단한다. 기존 Fillout과 원본 초안은 보존한다. Notion 속성·매핑·일지를 삭제하지 않는다. 전체 계정 확대는 별도 승인 후 진행한다.
